# Debate Log

## Round 1 — Bundled roadmap attack

- **Attack:** Session continuity and a frontend FSM were scored as one item.
- **Resolution:** Native resume became a backend-specific behavioral slice. Frontend state extraction is deferred until a real event contract requires it.
- **Attack:** Direct manipulation, version history, and design-system validation were bundled.
- **Resolution:** Each now has its own user failure, persistence impact, undo semantics, prerequisite, and manual QA gate.
- **Attack:** A `data-*` contract plus DrawingML was treated as export fidelity.
- **Resolution:** HTML remains canonical; a typed view is derived only for a named consumer, and PPTX support advances fixture by fixture.

## Round 2 — Trust and evidence attack

- **Attack:** Loopback binding was treated as an authorization boundary.
- **Resolution:** Hostile-Origin/Host negative tests and a per-launch capability became Gate 0.
- **Attack:** “Local-first” was phrased as zero egress.
- **Resolution:** The report now says the workspace/system of record is local while model processing follows the selected CLI/provider policy.
- **Attack:** Installable skills and read-only MCP were treated as low-risk.
- **Resolution:** Both were removed from P0 and require provenance, consent, workspace trust, and a concrete task.
- **Attack:** Repository stars, README fidelity claims, and shared PptxGenJS lineages were counted as independent evidence.
- **Resolution:** Stars are discovery signals only; unexecuted fidelity remains unverified; Shuttleslide and ppt-master count as one lineage.

## Final verdicts

- **Support P0:** authority test/boundary, exact CLI diagnostics, workspace trust, symlink-safe filesystem, import/export budgets, deterministic design-system report, per-turn diff, portable bundle.
- **Conditional:** native session resume after a cold-restart fixture.
- **Hold:** persistent process, generalized direct manipulation, derived deck manifest, PPTX image/shape coverage, multiple directions.
- **Reject/defer:** remote skill marketplace, network MCP, collaboration, infinite canvas, full framework codegen, provider matrix.

## Round 3 — Security and license red-team

- **Attack:** “strict Host/Origin” implied one policy for browser, SSE, bootstrap and non-browser clients.
- **Resolution:** BG-01 now requires a channel-specific authority matrix; Host is not identity, missing Origin is handled by channel, and same-user local processes are explicitly outside the browser capability guarantee.
- **Attack:** “realpath-safe” ignored sibling-prefix bugs, Windows junctions and validation-to-write races.
- **Resolution:** BG-04 now requires segment containment, component-level link/reparse rejection, root identity and a tested race model.
- **Attack:** archive ratio and timeout did not bound actual decompression, XML/PDF/image bombs or in-process memory.
- **Resolution:** BG-05 now requires numeric declared and streamed budgets, killable parsers, measured RSS/CPU/temp and cleanup receipts.
- **Attack:** network denial and secret scanning were treated as stronger guarantees than they are.
- **Resolution:** BG-06/BG-10 now require browser-context routing before navigation, service-worker/popup fixtures, explicit artifact dependency allowlists, best-effort scanning and clean-temp binary archive inspection.
- **Attack:** repository-level license labels hid mixed, source-available, copyleft and vendored paths.
- **Resolution:** implementation gates now require pinned per-path provenance, NOTICE review, runtime/export SBOM, and hostile AGPL/source-available seed rejection.

## Round 4 — App-builder overclaim attack

- **Attack:** Dyad's git substrate was treated as a checkpoint replacement without disk/latency or restore-parity measurement.
- **Resolution:** the report retains only the linear-copy fact and makes Git one benchmark candidate after bounded snapshot retention/GC.
- **Attack:** Onlook's JSX OID repair was promoted to automatic BurnGuard normalization.
- **Resolution:** duplicate-ID wrong-target behavior is accepted as an integrity gap; a read-only fail-closed validator comes before deterministic repair.
- **Attack:** complementary repo features were described as an observed universal five-step convergence.
- **Resolution:** visual targeting and change control are now separate BurnGuard design hypotheses joined by a change-set ID only after one vertical slice proves them.
- **Attack:** “proprietary” and “off-limits for close reference” overstated Dyad's FSL terms.
- **Resolution:** Dyad is labeled mixed Apache/FSL and current `src/pro/` is non-donor for competing-product implementation; behavior is independently specified and tested.
