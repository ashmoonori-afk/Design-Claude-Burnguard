# Excursion Log

## X-01 — Claude Design identity

- **Question:** Is Claude Design simply generic Artifacts?
- **Result:** No. Official sources describe a distinct Labs beta with a dedicated chat/canvas workspace, design systems, organization permissions, direct manipulation, formal exports, and Code/MCP handoff.
- **Changed:** Artifacts-only capabilities were excluded from the Claude Design inventory.

## X-02 — Editable HTML to PPTX

- **Question:** Has an open-source project solved full editable fidelity?
- **Result:** No verified universal solution. Projects use image flattening, DOM walking, an intermediate representation, or delegated office conversion, each with losses.
- **Changed:** “Parity” was replaced with an element support matrix and cross-app fixture gate.

## X-03 — Canvas architecture

- **Question:** Should BurnGuard adopt an infinite shape store or canonical slide JSON?
- **Result:** Current HTML identity and iframe bridge are functional. Shape-store evidence comes from spatial/collaborative products and is a false analogy for unrestricted HTML.
- **Changed:** HTML remains canonical; derived typed views require a named consumer.

## X-04 — Ecosystem breadth

- **Question:** Should BurnGuard match Open Design, Onlook, Dyad, or bolt.diy feature breadth?
- **Result:** Their strongest transferable patterns are typed lifecycle events, durable element identity, visible action/diff state, and package boundaries—not provider, plugin, or cloud breadth.
- **Changed:** Marketplace, provider matrix, cloud runtime, and collaboration were made non-goals.
