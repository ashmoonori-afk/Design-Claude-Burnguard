## 1. 이번 PR에서 수정한 항목

### 1.1 아티팩트 식별자 계약 (D18, D19, D20, D36, D43, D47, D48, D66, F16)

백엔드는 모든 변경 요청에 낙관적 동시성 앵커(`revision` + `digest`)를 요구하지만
프론트엔드는 이를 보내지 않았다. 재현 결과 편집 저장, 스타일 적용, 코멘트 핀 생성,
그리기 저장, 턴 되돌리기가 모두 400으로 실패했고 프로젝트 삭제는 capability 헤더
누락으로 403이었다. 턴 되돌리기는 그 이전에 사전 스냅샷 자체가 기록되지 않아
`writePreTurnSnapshot` 호출부가 없는 상태였다.

### 1.2 턴 종료 후 캔버스 갱신 (D8, D64)

백엔드는 어댑터의 `file.changed`를 버리고 `artifact.operation` 하나로 합쳐 발행하는데
프론트엔드는 전자만 처리했다. 이제 커밋된 `artifact.operation`을 처리하되, 사용자가
보고 있던 탭을 빼앗지 않는다.

### 1.3 턴 런타임 (D10, D11, D13)

Windows에서 중단 신호는 `claude.cmd` 래퍼만 종료시켜 실제 CLI가 계속 실행되었다.
이제 중단 즉시 소유 프로세스 트리를 정리한다. 종료 시 실행 중인 턴을 먼저 중단하며,
`is_error` 결과를 채팅에 오류로 표시하여 로그인 만료나 한도 초과가 침묵하지 않는다.

### 1.4 Chromium 실행이 백엔드를 정지시키는 문제 (D1, D15, D26 및 신규 확인)

리뷰가 지적한 것보다 심각한 사실을 계측으로 확인했다. Windows + Bun 1.3.13 +
playwright-core 1.59.1 환경에서 `chromium.launch()`가 핸드셰이크를 기다리는 동안
**Bun 이벤트 루프 전체가 멈춘다.** 3초 대기 구간에서 200ms 타이머가 18회 발화해야
하는데 1회만 발화했다. 그 결과 홈 화면이 카드마다 요청하는 썸네일 렌더 하나가 서버
전체를 세우고, 프로젝트를 열면 "프로젝트를 불러오는 중..." 화면에서 멈췄다. 요청
단위 타임아웃으로는 해결되지 않는다. 타임아웃을 발화시킬 타이머도 함께 멈추기
때문이다.

수정: 자식 프로세스에서 한 번 실행 가능 여부를 확인하고(`chromium-capability.ts`),
`launchChromium`이 그 결과를 먼저 확인한다. 실행할 수 없는 환경에서는 내보내기,
디자인 감사, 썸네일이 즉시 실패하며 서버를 멈추지 않는다. 썸네일 요청은 자체 응답
기한 안에 반드시 응답하고, 남은 렌더는 배경에서 캐시를 채운다.

### 1.5 홈 화면 (F16, F17, F18, F19, D2, D4, D32)

`최근`과 `내 디자인` 탭이 같은 목록이었고 둘 다 시드 예제를 포함했다. 템플릿에서
만든 프로젝트가 템플릿 배지를 달았다. 디자인 시스템 탭에는 로딩·오류·빈 상태가
없었다. 삭제 차단 사유는 프론트엔드가 읽지 않는 위치에 담겨 있었고, 안내 문구는
존재하지 않는 기능을 가리켰다.

### 1.6 접근성과 한국어 조판 (D29~D35, D40~D42, D63, D17, F20)

문서 언어가 `en`이었고, 토스트는 보조 기술에 전달되지 않은 채 3초 만에 사라졌으며,
채팅 입력에는 접근 가능한 이름이 없었다. 스타일 팝오버는 `bg-popover` 토큰이
정의되지 않아 배경이 투명했다. 권한 대화상자는 Esc나 바깥 클릭으로 턴을 중단시켰다.

### 1.7 Windows 테스트 이식성 (D50, D55)

백엔드 테스트가 개발자의 실제 `~/.burnguard`에 기록했고, 경로 계산과 심볼릭 링크,
macOS 전용 도구 가정 때문에 약 45건이 환경 문제로 실패했다. 이제 23건이며 나머지는
아래에 정리한 기존 실패다.

## 3. 알려진 잔여 실패

- 백엔드 테스트 23건 실패(기준선 약 45건). 내역: 디자인 감사·그래픽 내보내기
  16건은 이 호스트에서 Chromium을 실행할 수 없어 실패하며, 이제 멈추는 대신 빠르게
  실패한다. 나머지는 Windows에서 심볼릭 링크와 열린 파일 교체를 쓸 수 없어 실패하는
  기존 항목이다(`session-recovery` 1건, `stage-attachment-inputs` 1건,
  `visual-source-security` 2건, `design-system-publication` 1건,
  `design-direction-routes` 1건).
- `export-render-lifecycle.test.ts`는 기준선에서도 결과를 출력하지 않고 멈춘다.
  이번 변경과 무관한 기존 문제이며 전체 실행에서 제외했다.
- E2E 스모크는 6회 중 5회 통과한다. 실패하는 회차는 편집 모드에서 캔버스 히트
  테스트가 응답하지 않아 편집 패널이 열리지 않는 경우이며, 프레임 브리지 준비 상태와
  1초 요청 타임아웃 문제(미검증 목록)와 같은 원인으로 보인다.
- `services/turns.ts`에 매 턴 디렉터리 목록을 출력하는 디버그 로그가 남아 있다.
  이번 변경 범위 밖이라 그대로 두었다.

## 4. 커버리지 노트

라이브 UI 감사는 격리된 홈 디렉터리에서 백엔드를 구동하여 1440×900, 1024×768,
390×844 세 뷰포트로 홈 네 탭과 새 프로젝트 패널 다섯 유형, 프로젝트 뷰, 설정을
캡처했다. 코드 리뷰는 백엔드 라우트 19개 전부, `design-system-extract.ts` 2157줄
전체, 프론트엔드 `src/components`와 `src/views` 전부를 읽은 것으로 보고되었다.
검증이 중단된 탓에 미완결 69건은 개별 확인이 필요하다.
